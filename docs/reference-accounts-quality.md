# Reference accounts 품질 심사 · 운영자 검수

2026-09-19. 이번 범위는 계정 추천의 검색·심사·캐시·카탈로그 관리뿐이다.
코드와 자동 테스트를 완료했고, 살림/인테리어 실제 데이터·AI 심사 후 44개 목록을 사용자에게 승인받았다.
추가 수집은 중단했다. 운영 DB import·배포 및 공급자 실제 청구서 대조는 수행하지 않았다.

## 추천 기준

- 카탈로그 우선, 검증 30일, 최근 활동 90일, 적격 카탈로그 5명 미만일 때만
  공개 검색하는 구조를 유지한다. 팔로워 최소 1만 및 선택 구간, 조회 50만 이상 콘텐츠 보유, 최근 릴스 12개 중앙값 1만 이상은 하드 필터다.
  12개의 고유한 릴스 날짜·조회수가 모두 필요하며 미확인 수치는 0으로 대체하지 않는다.
  국내 활동 계정만 대상으로 하며 domesticCreator=true와 공개 근거가 없으면 제외한다.
  한국어·한국 이름만으로 국내 활동을 추정하지 않는다.
- SERP 제목/설명/username에서 명백한 연예인·모델·소속사·MCN·미디어·브랜드를
  프로필 수집 전에 제외한다. 프로필에서만 드러나는 신호는 프로필 수집 후,
  유료 릴스 조회와 LLM 심사 전에 제외한다. 최초 SERP 검색 자체는 유료다.
- 구조화된 LLM 심사는 ordinaryCreator=true, productionLevel=personal 또는
  semi_pro일 때만 통과한다. false/null, professional/unknown 및 누락 필드는 제외한다.
  외모의 아름다움·평범함은 심사하지 않는다.
- accountTypeEvidence, ordinaryCreatorEvidence, productionEvidence,
  replicability(0–100), replicabilityEvidence, monetizationEvidence,
  monetizationSourceUrls, evidencePostUrls를 함께 저장한다. 근거 게시물 링크는 실제
  수집한 exampleMedia 안에 있어야 한다. 수익화 링크는 그 게시물 또는 externalUrl이다.
  링크의 존재 검증은 내용의 진실성 검증을 대신하지 않으므로 운영자 확인이 필요하다.
- 기존 적합도 65% + 재현 가능성 25% + 팔로워 대비 조회 점수 10%로 점수를 계산한다.
  조회 점수는 min(100, 최근 릴스 중앙값 / followers × 10), 팔로워 0명일 때는 0이다.
  수익화 근거가 []이면 35점 감점하고, 그것만으로 제외하지 않는다. 최소 결과 수를
  채우기 위한 허위 계정이나 완화된 조회 조건은 없다.

## 기존 카탈로그와 Redis

추천 요청에는 카탈로그 upsert가 없다. 유일한 저장 경로는 아래 운영자 import다.
기존 JSONB profile에 qualityVersion=3, reviewedByOperator=true, reviewedBy,
reviewedAt와 카테고리별 accountInsights의 새 심사 근거가 모두 있어야 재사용한다.
검수일은 수집일 이후이면서 최근 30일이어야 한다. 기존 행은 삭제하거나 자동 승인하지
않으며 필드가 없으면 추천 풀에서 빠진다. 재수집·운영자 재검수가 필요하다.

검색 v10 / 카테고리 풀 v7 / ranking v5으로 캐시 키를 변경했다. 이전 키를 승인 자료로
사용하지 않는다. 새 키도 읽을 때마다 날짜·휴리스틱·수치·최종 심사 필드를 검사한다.
카테고리 풀은 **심사 전 공개 증거** 캐시이며 운영자 승인 카탈로그가 아니다.
라이브 후보는 새 LLM 심사를 통과하면 현재 요청의 결과로 표시할 수 있지만, 자동 저장되거나
운영자 검수 완료로 표시되지 않는다. 심사 필드가 없는 ranking은 추천에서 제외된다.

## 1단계: 비용 계획 → 명시적 승인 → 검수 파일

실제 호출 전에 공급자 계약과 모델의 최대 입력/출력 비용을 확인하고, 다음 예약 단가를
환경변수로 지정한다. 저장소의 실제 .env 키·토큰은 출력하지 않는다.

| 환경변수 | 의미 |
| --- | --- |
| CREATOR_CATALOG_POLL_MS | 카탈로그 수집 상태 확인 간격, 기본 30,000ms, 허용 10,000~60,000ms |
| CREATOR_CATALOG_CATEGORY_MAX_CALLS | 카테고리당 모든 공급자 요청 상한, 기본 100 |
| CREATOR_CATALOG_CATEGORY_MAX_USD | 카테고리당 예약 비용 상한, 기본 US$2 |
| CREATOR_CATALOG_SEARCH_USD | SERP 요청 1건당 보수적 비용, 필수 |
| CREATOR_CATALOG_PROFILE_USD | 요청 프로필 1개당 보수적 비용, 필수 |
| CREATOR_CATALOG_REEL_USD | 요청 릴스 1개당 보수적 비용, 필수 |
| CREATOR_CATALOG_RANK_USD | 이미지·입력·최대 6,000 출력 토큰을 포함한 심사 1회 최대 비용, 필수 |

각 단가는 양수여야 한다. 임의의 최신 요금을 내장하지 않는다. 먼저 실행 옵션 없이:

```sh
npm --prefix backend run warm-creator-catalog -- --category="살림/인테리어"
```

이 명령은 DB/Redis 연결이나 유료 호출 없이 계획을 출력한다. 1페이지 검색 5회,
프로필 20개 수집(요청 3회), 릴스 최대 480개 수집(요청 6회), LLM 1회인 **15회 시나리오**의
비용과 카테고리/전체 상한을 보여준다. 캐시 적중은 0회도 가능하고 검색 확장·폴링은
더 많이 필요할 수 있어 예상치는 보장치가 아니다. 요금 설정이 없으면 실행을 거절한다.
`--all`은 모든 카테고리의 합산 상한을 출력한다.

출력된 비용 계획에 대해 이번 실행의 명시적 승인을 받은 뒤에만:

```sh
npm --prefix backend run warm-creator-catalog -- --category="살림/인테리어" --execute --approve=<출력된-plan-id> --output-dir=output/catalog-review
```

`--execute`만으로는 실행되지 않는다. 카테고리·단가·상한·모델이 바뀌면 승인 ID도 바뀐다.
프로필/릴스 trigger 전에 전체 요청 레코드 비용을 예약한다. 실패한 호출도 예약을 환급하지
않는다. progress/download도 호출 수에 포함하며 해당 비용은 레코드 단가에 포함해야 한다.
상한에 도달하거나 다음 예약이 상한을 넘으면 즉시 중단하고 이후 카테고리도 실행하지 않는다.
기존 providers.js의 일일 예산/서킷브레이커는 그대로 적용된다. 이미 시작된 공급자 수집은
중단 후에도 완료·청구될 수 있다. 상한은 설정한 단가에 따른 예약 상한이며, 실제 청구 보장은
아니므로 보수적 단가 및 공급자 계정 자체의 지출 한도를 함께 사용한다.

JSON은 프로필 URL, 수집일, 팔로워/조회수, viralMedia, exampleMedia, 카테고리별 판정과
근거 링크를 보존한다. 모든 레코드는 reviewedByOperator=false로 출력한다.
LLM에서 거절/unknown인 후보도 검수 파일에 남고 automaticDecision으로 구별한다.
수집 전 휴리스틱에서 탈락한 계정은 파일에 포함되지 않는다. 프로필 수집 완료 시부터 검수 파일에
남기고, 수치 필터 탈락·조회 누락 후보도 performance와 미심사 상태로 표시한다.
도중 중단 시 프로필 수집 완료 후보가 없으면 빈 배열 파일이 남는다. 계정을 만들어 넣지 않는다.

## 2단계: 운영자 확인 후 별도 import

운영자가 공개 프로필과 근거 게시물을 직접 확인한다. 승인할 레코드만 새 JSON 배열에
남기고 각 레코드 최상위의 reviewedByOperator=true, reviewedBy(검수자 식별자),
reviewedAt(ISO 일시)를 직접 기록한다. 심사 필드와 원본 근거를 함께 검토한다.
professional=true는 기존 카탈로그 적격 플래그이며 고비용 professional 제작 수준이나
Instagram 비즈니스 계정 여부를 뜻하지 않는다.

```sh
node backend/scripts/manage-creator-tools.js catalog <reviewed.json>
```

전체 파일을 먼저 검증하고 하나라도 미승인·구스키마·누락 근거·기한 만료·잘못된 지표가
있으면 DB 쓰기 전에 거절한다. 승인 기록과 accountInsights, categories, 수치를 모두
JSONB에 보존하여 username 기준으로 upsert한다. 별도 스키마 마이그레이션은 없다.
자동 수집 명령은 이 import를 호출하지 않는다. 운영 DB import는 별도 승인이 필요하다.

### 실제 풀 수집: 최근 릴스 표본 확보 보완

2026-09-19 프로필 수집 결과는 사진/캐러셀이 섞인 최근 게시물 12개라서,
6개 후보의 릴스 표본이 1~8개에 그쳤다. 일부 표본으로 중앙값 조건을 완화하지 않았다.
공식 [릴스 전체 조회 API](https://docs.brightdata.com/api-reference/scrapers/social-media-apis/instagram-reels-collect-all)의
프로필 단위 수집을 사용한다. 첫 실검증에서 num_of_posts=12 응답에 오래된 고정 게시물이
포함됨을 확인하여, 최종적으로 `num_of_posts=24`와 `limit_per_input=24`를 지정한 뒤
게시 날짜순 최신 12개만으로 중앙값을 계산한다. 최고 조회수 기준은 수집된 전체 표본의
검증된 조회수로 따로 판정한다. 고정 게시물의 큰 조회수가 중앙값을 부풀리면 안 된다.
계정당 최대 24개 레코드 비용을 trigger 전에 예약하고 기존 일일 한도/서킷브레이커를 거친다.
표준 20명 시나리오는 프로필 20개, 릴스 최대 480개, LLM 1회이며 파일럿 예약 단가로
US$3.765다. 이전 US$3.045는 12개씩 조회하던 당시 시나리오다.

공식 문서에 따르면 릴스 게시일은 제공되지 않을 수 있고 2026년 8월부터
start_date/end_date 입력을 지원하지 않는다. 날짜를 생성하지 않는다. 날짜가 없는
24개 표본에서 최신 12개를 확정할 수 없으므로 그런 계정은 미검증으로 남긴다.
선택 근거(method, requestedCount=24, profileUrl, collectedAt)와 소유자를 함께 기록한다.
12개 미만, 최신 12개 조회수 누락, 날짜 누락, 소유자 불일치, 오래된 수집 근거는 통과하지 않는다.
24개 초과 응답은 거절한다. 구 12개 수집 checkpoint와 캐시를 최신 12개 증거로 재사용하지 않는다.

수량 목표는 [카테고리별 풀 구성안](reference-accounts-pool-plan.md)을 참고한다.
