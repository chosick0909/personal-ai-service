## 근본 변경

- 기존 자동 자막은 ASR의 긴 segment 그대로였다. 기존 분할은 `Array.from(text)`의 글자 중앙과 시간 중앙을 강제했다.
- `shared/subtitle-layout.mjs`가 서버 자동 묶기, 사용자 선택 분할, 미리보기, MP4 배치의 공통 계약이다. 원문 어절 경계만 허용하고 한 단어는 자르지 않는다. 기본은 1~3어절·약 14자 안팎이다. 긴 단어는 축소한다.
- ASR words를 원문 segment 전체와 정렬할 수 있을 때만 단어 발화 시간을 쓴다. ASR words가 원문과 다르면 원문을 보존하고 시간만 비례 추정한다. 추정임을 UI에 표시한다. 원문을 ASR word 목록으로 대체하거나 단어를 유실시키지 않는다.
- 500개 제한은 유지한다. 밀도가 높은 영상에서는 짧은 인접 자막부터 합치며 내용을 버리지 않는다.
- 사용자가 단어 뒤 경계를 선택하고 원본 시간(초)을 입력하거나 현재 재생 위치를 선택한다. 0.08초 미만 조각·빈 조각은 만들지 않는다. 실행 취소/다시 실행, 합치기, 저장/재열기가 유지된다.
- 영상 분할은 기존 타임라인 재생 위치에서 실행한다. 원본 시간 자막은 기존 클립 투영 로직으로 출력 시간에 맞춘다.
- 새 분석은 기본 스타일·MP4 자막 포함을 설정한다. 기존 프로젝트를 자동 재분할하지 않는다. 기존 프로젝트의 스타일 없는 내보내기는 기존처럼 자막 없는 MP4다. 사용자가 스타일/포함 여부를 명시적으로 바꿀 수 있다.
- 기존 긴 자막은 ‘짧은 자막으로 나누기’를 누르면 현재 편집본에서 나뉜다. 기존 컷/원문/진단을 되살리거나 초기화하지 않는다.
- JSON manifest에 enum 스타일과 burnIn boolean만 추가했다. DB schema/권한/이용권/모델/환경변수 변경 없음. 서버 원본 words·진단은 클라이언트가 덮어쓰지 못한다.
- `renderMedia()`는 기존 trim/concat과 같은 FFmpeg 호출에서 ASS 자막을 합성한다. 별도 전체 재인코딩 단계를 추가하지 않는다. 사용자 문장을 ASS 제어 명령이나 필터 경로로 실행하지 않는다. SRT와 원본 ZIP도 유지한다.

## 검증

- `backend/test/creator-subtitles.test.js`: 한국어/영어/일본어/아랍어/이모지, 숫자·URL, 긴 단어, 정렬 불가 ASR, 빠른 발화, 5분 고밀도, 사용자 지정 단어/시간, invalid 시간, 스타일 유효성, 컷 후 SRT.
- `backend/test/creator-subtitle-render.test.js`: 실제 `renderMedia()`·FFmpeg로 세 스타일+미포함 MP4 생성, 디코딩 픽셀의 흰 자막 존재, SRT 재배치, ZIP 원본 바이트 일치. 실제 `analyzeMedia()`의 추출/미리보기 처리도 실행하고 ASR·DB만 모의 처리해 새 자동 자막·스타일을 확인한다.
- 실제 media GET/PATCH 핸들러에서 스타일·단어 시간·분할 저장/재조회, 소유자 격리·stale revision 거부.
- 실제 React `CreatorMediaEditor` + Chrome에서 단어/시간 지정, undo/redo, 스타일 표시, 저장/재열기, 내보내기 호출, 재분할, 390px 가로 넘침 0 확인. API/인증은 합성 환경이다.
- 기존 실제 App 흐름(스튜디오 한글 인계 → A/B/C → 단일 에디터 → 버전/복원/PDF → 분량 조절 → stale 제안 방어), 네이티브 릴스 3개 실제 재생, 삭제/실패 카드 제외, 영상 실패의 원래 오류 표시도 재확인.

상세 실행 로그·이미지·집계는 외부 검증 폴더 `creator-subtitles-20261021`에 보관한다. 자동 테스트 성공은 실제 사람 만족도나 운영 로그인/저장 성공을 의미하지 않는다. ASR 자체 정확도와 시간 추정 오차, 원본과 근사 서체의 차이는 남는다. 로컬 Docker daemon이 꺼져 있어 새 Linux 이미지 빌드·Railway 네트워크 실행은 배포 성공 후 확인해야 한다.
