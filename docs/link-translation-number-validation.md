## 실제 실패 기록

대상: https://www.instagram.com/reel/DW8tMKyiTxO/

이 URL로 한정한 읽기 전용 조회에서 저장된 작업의
`TRANSLATION_NUMBER_CHANGED` 실패를 확인했다. Bright Data 수집, 힌디어 전사(18구간),
최초 번역 및 보정 번역의 공급자 요청은 모두 성공했다. 번역 결과 자체는 저장되지 않아
실제로 어떤 번역 구간이 차단됐는지는 단정할 수 없다.

저장된 원문에는 숫자로 적힌 99.9%, 254와 말로 표현한 five-in-one, 한 병,
두 달 등의 수량이 함께 있다. 기존 검증은 ASCII 숫자 목록의 일치만 검사했다.
따라서 말로 표현한 수량을 올바르게 5-in-1, 1병, 2개월로 번역해도 새로운 숫자로
간주해 거절한다. 이 오탐 조건을 실제 원문의 수량 패턴으로 재현했다.
반대로 문자가 유지된 채 수량/단위가 달라지는 경우는 숫자 목록만으로 잡을 수 없다.

## 수정 범위

- Creator Studio 링크 추출의 `link-import.js` 및 관련 테스트/문서만 수정.
- 언어별 숫자 단어 사전이나 특정 URL 예외를 사용하지 않는다.
- 숫자로 적힌 원문은 자리표시자로 보호한다. Unicode 십진 숫자도 포함한다.
  누락·중복·다른 구간으로의 이동을 코드로 차단한다.
- 원문에 말로 표현된 수량이 번역에서 숫자가 되는 것은 그 자체로 오류가 아니다.
  별도 구조화된 모델 검증에서 모든 구간의 수량·횟수·기간·가격·단위·비율·제품명
  의미를 대조한다. 원문과 번역의 실제 부분 문자열을 근거로 요구한다.
- changed/uncertain, 누락된 구간, 잘못된 id, 실제 문장에 없는 근거는 승인하지 않는다.
  이 검증은 모델의 의미 판단을 포함하므로 모든 언어의 정확성을 보증하지 않는다.
- 단순 자리표시자 복사 오차만 제한적으로 복구한다. 문장 다른 곳의 숫자를 임의로
  삭제해 검증을 통과시키지 않는다.
- 통상 번역 1회 + 의미 검증 1회. 실패하면 보정 1회 + 의미 검증 1회로 제한한다.
  최대 OpenAI 4회이며 기존 provider 예산·서킷브레이커를 그대로 거친다.
  provider 예산/네트워크 오류에 대해 추가 번역을 실행하지 않는다.
- `translationV2` checkpoint로 이전 숫자 검증을 거친 번역 checkpoint와 구분한다.
  기존 transcript checkpoint는 재사용한다. 완료된 DB 레코드를 소급 변경하지 않는다.
- 기존 /analyze, writer, 계정 추천 필터, 로그인, 저장, PDF는 수정하지 않는다.

## 2026-09-30 링크 번역: 문장 수가 아닌 의미 보존

사용자 결정: 한국어 번역의 문장·줄 수가 원문과 달라도 된다. 정확한 번역과 후킹·설득 구조 분석이 우선이다. 이 절은 위의 구간 일대일 반환 요구를 링크 분석에 한해 대체한다.

### 확인한 원인
- 기존 `translateSegments`는 Whisper 시간 구간을 배열로 전달하고 모델이 같은 ID/길이/순서로 반환하도록 요구했다. `checkedRows`는 배열 길이가 다르면 `TRANSLATION_INVALID`를 즉시 발생시켰고 보정 대상은 수량 오류뿐이었다.
- 합성 원문 3구간 → 한국어 1문장 사례를 배포 기준 78c1972에서 실행하여 실제 “번역 문장 수가 원문과 다릅니다.” 오류를 재현했다. 유효한 문장 합치기도 실패시킬 수 있는 계약 결함이다.
- 제보 URL은 Dc4D3TLTBpB. 해당 운영 작업의 원문·모델 응답·로그를 읽거나 영상을 재수집하지 않았으므로, 실제 사례가 정상적인 합치기인지 누락이었는지는 미확인이다. 합성 재현을 실제 영상 재현으로 쓰지 않는다.

### 최종 수정
- 짧은 전사는 문맥 전체를 단일 text로 번역한다. 모델이 반환하는 문장 목록·개수·ID 계약을 제거했다. 한국어 문장을 자연스럽게 합치고 나눌 수 있다.
- 긴 전사는 3,000자 이내 문맥 단락으로 나누고 인접 원문 최대 500자씩을 읽기 맥락으로 제공한다. 입력은 순서대로 빠짐없이 포함하며 문장·전사 구간 개수가 분할 기준이 아니다. 단락이 성공한 뒤 다음 단락 보정 때문에 앞 단락을 다시 생성하지 않는다.
- 기존 숫자 자리표시자 보호를 유지한다. 기존 독립 수량 검증 호출에서 핵심 의미·조건·부정·대상·행동·훅/설득 흐름 보존도 확인한다. 원문 내용의 진위 판단이 아니라 번역 충실성 판단이다. 모델 검증의 오탐·미탐 가능성이 없어지는 것은 아니다.
- 빈 응답·수량 변경·의미 누락/추가/불확실성은 해당 단락에서 한 번만 보정한다. 예산·네트워크·취소·잘린 응답 오류에는 이 번역 함수가 별도 재시도를 추가하지 않는다. 실패한 번역을 완성본으로 저장하거나 분석에 넘기지 않는다.
- 번역당 원래 쓰던 모델 선택/operation 설정을 유지한다(`translate-reference`, `translate-reference-correction`, `verify-reference-numbers`). provider 설정·모델 변경 없음. 짧은 입력은 통상 기존과 같은 번역 1회 + 검증 1회, 최악 4회다. 긴 입력 N단락은 통상 2N회, 최악 4N회라 호출·지연이 늘 수 있으며 실측하지 않았다. 전역 예산·90초 요청 제한·기존 워커 마감은 유지한다.
- 기존 성공 `translationV2` 체크포인트는 그대로 재사용한다. 모델에서 받은 새 형식은 내부에서 text 행 배열로 바꿔 기존 결과 조립과 저장 형식을 유지한다. 완료 기록 소급 변경 없음. 작업이 중단되어 재개될 때는 기존처럼 전체 번역 체크포인트가 없으면 번역부터 다시 할 수 있다.
- 번역 결과를 먼저 표시하고 그 정확한 번역문으로 분석하는 흐름 유지. /analyze·코파일럿·컷 편집 자막/타임라인·UI·DB·이용권 차감은 수정하지 않았다. translateSegments의 제품 호출자는 importLink 하나임을 검색으로 확인했다.
