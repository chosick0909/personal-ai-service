## 원인
referenceReviewPrompt가 `자신의 주제로 독립적으로 기획할 질문`이라고만 지시하고 문자열 배열만 받았다. 수강생·추천 계정 운영자·시청자 역할이 구분되지 않았고, 공개 수익화 심사와 같은 출력에서 공구 선정·협찬·개인 피드백 인터뷰가 기획 포인트에 유입됐다. catalogOnly 경로는 저장된 accountInsights를 그대로 쓰고, 과거 creator_jobs도 저장된 result를 바로 반환하므로 생성 프롬프트만 고쳐서는 기존 화면이 바뀌지 않는다.

## 수정
- 미래 생성: 수강생이 자기 자료로 제작하는 주제(title), 시청자 문제(viewerProblem), 촬영 장면(filmingPlan), 착안한 제공 게시물(sourcePostUrl)을 명시한 구조로 변경. 촬영/시청자 설명 누락 및 제공하지 않은 출처는 주제로 채택하지 않는다. 글 끝 물음표/특정 단어를 바꾸는 정규식 없음.
- 기존 44개: 저장된 분석을 근거로 132개 기획 주제를 편집. 최초 승인 카탈로그·조회수·추천 심사·검증일은 변경하지 않았다. 최초 문구와 일치하는 계정·카테고리에만 버전 있는 교정 자료를 적용한다. 새로 검토된 문구를 덮어쓰지 않는다.
- 신규 조회와 과거 작업 재열기: discoverAccounts 및 모든 publicJob 응답에 같은 교정을 적용. 운영 DB 갱신, 재수집, 읽기 시 유료 호출 없음. 이미 열어둔 화면은 재열기/새로고침이 필요하다.
- 새 출력 계약의 이전 Redis 재사용 방지: ranking v5 → v6. catalogOnly는 여전히 Redis/모델/worker 없이 즉시 반환한다.
- 알 수 없는 과거 문구/다른 카테고리는 임의로 살림 주제를 끼워 넣지 않는다. 주제만 검토 중으로 표시하고 추천 계정·순위는 유지한다. 이번 44개 저장 자료는 모두 교정 대상에 포함됨.
- 화면에는 내 콘텐츠로 만들 주제임을 안내한다.
